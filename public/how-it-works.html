    How it works

    Iris turns a PDF into accessible HTML. AI Models read and write. Code Code prepares their input, checks their output and throws away replies that lose content. If asked, iris-pdf then tags the original PDF, using code only.

    The same in words
    1. Each page. Code The page becomes an image, and form fields are read. AI The page agent writes its HTML. AI A second model checks it against the image, and Code rules check links, image descriptions and ids. A failed page is fixed once.
    2. The whole document. Code Pages are joined and checked with axe-core. AI A reader lists problems and AI a copy editor fixes them, for a few rounds. Code A fix that loses content is thrown away. What is left is listed in the HTML.
    3. Tagged PDF, if asked. Code iris-pdf matches the HTML's words to the PDF's, tags the text in place, adds form fields, and checks every page before saving.
    Words the run log uses
    Page agent
    The model call that writes one page's HTML from its image.
    Verdict
    The checking model's answer about one page: is it faithful to the image, and is it accessible.
    Fragment
    One page's HTML, before the pages are joined.
    Block
    One top-level part of the joined document. The copy editor changes the document block by block.
    Round
    One pass of the review: the reader lists problems, then the copy editor fixes them.
    Declaration
    The page agent saying a page is blank. Iris can refuse it, for example for a page that is only too dark to read.
    Run
    One conversion of a document. Feedback starts a new run of the same document.
